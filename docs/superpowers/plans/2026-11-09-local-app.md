# Local EasyPG implementation plan

> **For agentic workers:** Use subagent-driven development with independent file ownership and final integration review. The user explicitly authorized immediate execution without approval pauses.

**Goal:** Run and test the existing SvelteKit application against an independent local PostgreSQL API, with quick touch-friendly resident registration.

**Architecture:** Static SvelteKit SPA on 5180 proxies `/api` to a separate sibling API on 5188. Dedicated PostgreSQL cluster on 5488. Existing DTO and operation boundaries remain authoritative.

**Tech Stack:** SvelteKit 2 / Svelte 5, Astryx, StyleX, Node.js, PostgreSQL 16, pg, Sharp, Vitest, Playwright.

**Spec:** `../specs/2026-11-09-local-app-design.md`

## Global constraints

- Do not alter either source comparison project.
- No database clients, server modules, migrations, credentials, or backend implementation in the frontend.
- Explicit demo/live modes; live failures never substitute demo data.
- Money is integer decimal paise strings across JSON.
- Synthetic data only; 390×844 without horizontal page scrolling and minimum 44 px touch targets.

## Review focus

- An uncertain submission must reuse its idempotency key; a different payload with that key must conflict.
- Competing admissions cannot allocate the same bed twice; registered people must not be duplicated.
- Unauthorized image reads and cross-scope requests must fail, including after logout.
- Invalid/oversized images must keep the form usable and must not write partial registration data.
- Registered people must not appear checked out or have fabricated balances/stays.

## Decisions / progress

- Three fast agents audited the frontend, sovereign source, and Astryx pilot. Both comparison folders remain read-only.
- Ruling: quick registration is distinct from admission because a person can be saved before inventory and financial terms are selected.
- Ruling: work remains in the requested local directory; independent agents have non-overlapping file ownership. No publish, deployment, or external messaging is needed.

- Final verification: 23 unit tests, 12 standard browser tests, 7 real-API browser tests (56 role/viewport screen visits plus full journey), and 7 PostgreSQL integration tests passed. Svelte check and static build passed. Runtime remains live at 127.0.0.1:5180. Full evidence and limits are in docs/VERIFICATION.md.
- Final-review fixes: operation dates cannot be future dates; Node 22.12 CLI compatibility verified; duplicate phones/stale draft scope produce conflicts; private invoice projections contain no internal property field.
